# Homepage tile order: what's actually happening

## What I checked
- The database: your order is being saved correctly. The positions I set were updated tonight (23:04 and 23:22) and run 0 to 24 with no gaps.
- The live site (octowonders.com): the homepage follows that saved order exactly, OCTOMUTATION included. So the link between the admin panel and the site is not broken.
- The admin panel: there is no drag and drop in the code at all. Reordering only works through the small up/down arrows in the product list.

## Why it looks like the order is ignored
1. **Tiles fill across, then pile into columns.** The gallery puts tile 1 in column 1, tile 2 in column 2, tile 3 in column 3, tile 4 in column 4, then goes back to column 1. The first row is in your order. Below that, the columns end up different heights because the images are different heights, so from the second row onward the tiles look shuffled. On a phone (one column) the order is exact.
2. **New products always go last.** "Aggiungi prodotto" gives a new artwork the last position, so OCTOMUTATION is number 24: the very last tile, at the bottom of column 4.
3. **Hidden products still count as positions.** Inactive artworks (for example "Octocubist - NOT FOR SALE YET" at position 0, and Trotella, OLIM and Get Green) are in the arrow list. When you move a tile past one of them, the arrow click works but nothing changes on the homepage.
4. **Clicking fast can undo your moves.** Every arrow click saves several products, one after another. If you click again before that finishes, the next click works from the old order and can overwrite the move you just made.
5. **The live site only changes after a deploy.** Saving changes the database straight away. octowonders.com only shows the new order after "Sync & Deploy", plus up to about 15 minutes of caching.

## Proposed fixes (nothing changes until you approve)
- **A. "Porta in cima" button** next to each product in the admin list. It moves that artwork to position 1 and pushes everything else down by one. This is the fastest way to get new releases to the top.
- **B. New products start at the top** instead of the bottom.
- **C. Safer arrows:** turn the arrows off while a save is still running, so fast clicks can't undo each other.
- **D. Optional, and it changes the look:** set the desktop gallery out in straight rows, so the order reads left to right, top to bottom. You would lose the staggered masonry look. I recommend skipping this unless you want it.

Not touched: page addresses, images, SEO, checkout, the deploy process.

## Technical details
- Gallery: `src/components/MasonryGrid.tsx` uses `react-masonry-css`, which deals tiles out across the columns in turn. Its DOM order on the live site matches `display_order` across 4 columns.
- Production reads the frozen `src/generated/staticProducts.ts` through `useStaticProducts`. This snapshot is regenerated by `scripts/prebuild.ts` on each Vercel build.
- Admin: `handleMoveProduct` (AdminPanel.tsx ~838) swaps positions using all products, including inactive ones. `handleProductsChange` runs updates one by one, then refetches, with no lock against overlapping clicks. `handleAddProduct` sets `display_order: products.length`.
- A: renumber so the chosen product is 0 and the others follow in their current order. This reuses `handleProductsChange`.
- B: insert at 0 and shift the others, using the same renumbering.
- C: an `isReordering` flag that turns off the arrows and the "Porta in cima" button until the refetch finishes.
- Pages to update for A, B and C: `src/components/AdminPanel.tsx` only. Option D would also change `MasonryGrid.tsx`.
